Set up the workshop

Most early frustration with this course is environment trouble, not AI. An hour spent getting the repo, the Python environment, your keys and a local model working means every later notebook just runs.

By the end of this module you can

  • Clone the repo, install its environment with uv, and open notebooks on the right kernel.
  • Store API keys safely in a .env file, or skip paid keys entirely with Ollama.
  • Diagnose the handful of problems that cause most setup failures.
  • Know what the course will cost you and how to keep it near zero.

The .env file

Every notebook starts with load_dotenv(override=True), which reads this file into environment variables, and then the client libraries pick up their keys automatically. Three details trip people up constantly, according to the setup guide: the file must be named exactly .env (not .env.txt), there's no space around the equals sign, and you have to actually save it.

Why keys live in .env and not in code

Notebooks get shared, pushed and pasted. A key in a cell ends up on GitHub sooner or later. The .env file is listed in .gitignore, so it stays on your machine. Treat it like a password file, and set a monthly limit and auto-recharge off on any paid account.

What it costs

The author's guidance in the README is that you shouldn't need to spend more than a couple of dollars on API calls for the whole course, using the cheapest models from each provider, and that paid APIs are optional: Ollama, Gemini's free tier and OpenRouter are covered as alternatives in Guide 9 of the guides folder. Weeks 3 and 7 use Colab GPUs, where the free tier or minimal spend is enough. A few steps are optional and cost more if you choose the large version: preprocessing the full 800,000-item dataset in Week 6 cost the author under $30 with Groq (the lite version is under $1, or free if you load his preprocessed copy), and the author spent about $10 on the full Week 7 training run.

When it doesn't work

  • Run setup/troubleshooting.ipynb. It walks through the kernel, imports, the .env file and a test call step by step.
  • Corporate networks: VPNs, firewalls and TLS inspection cause SSL errors and blocked downloads. Test on a phone hotspot to prove whether it's the network.
  • Windows: the 260-character path limit, permissions, and missing Microsoft Build Tools are the usual culprits; the setup guide links fixes for each.
  • Mac: install the Xcode command-line tools if compilers are missing.
  • Name errors in a notebook almost always mean a cell above wasn't run. Restart the kernel and run from the top.
  • A model stops working: providers retire models every few months. Swap in the closest current model from the same provider.

Skim the list now and come back when a week assumes something you haven't met.

How to study this course

  • Run every cell and read every output. The author runs the code during the lectures, and the labs are designed for you to change things and see what happens.
  • Keep a lab notebook of your own. One markdown file per week: what surprised you, what broke, what you changed.
  • Look at community contributions. Each week's folder has a community-contributions directory of students' versions of the exercises. They're a good source of ideas after you've tried yourself. You can add yours by pull request; Guide 3 explains the git steps, and the author asks that PRs touch only that folder, have notebook outputs cleared, and stay small.

Takeaways

  • uv sync gives you the exact environment the labs expect; choose the .venv kernel in each notebook.
  • Keys go in a file named exactly .env in the project root; Ollama means you can do almost everything without paying.
  • Expect a few dollars of API spend, plus optional extras for full-size runs in Weeks 6–7.
  • Pull the latest code each week, and swap in current model names when old ones retire.

Check your understanding

A notebook says your API key isn't found, but you created the file. What's the most likely cause?

The setup guide singles out file naming and saving as the most common problem by far. The loader only looks for a file named exactly .env.

In this project, how do you add a new package?

uv add updates pyproject.toml and the lock file and installs into the project's .venv, so everything stays reproducible.

You'd rather not pay for any API. What's the plan?

Every OpenAI-style call in the course can point at Ollama's local endpoint instead, at the cost of using smaller, less capable models.
