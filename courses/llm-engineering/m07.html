The Price Is Right: data, baselines and frontier models

The capstone starts here and runs to the end of the course: a model that estimates a product's price from its description. Week 6 is the data-science half of LLM engineering: curate a dataset, clean it with an LLM, define an honest evaluation, and see how far traditional machine learning, a neural network and frontier models get before any fine-tuning.

By the end of this week you can

  • Curate a training set from a large public dataset, with explicit filters and a balanced distribution.
  • Use an LLM in batch to rewrite messy records into a consistent format, cheaply.
  • Define one evaluation and run every approach through it, starting with simple baselines.
  • Explain how traditional ML, neural networks and zero-shot frontier models compare on this task.

Project: The Price Is Right, part 1

  1. Load product metadata from several categories of the public Amazon Reviews 2023 dataset with the datasets library, parse each item into title, text, category, weight and price, and filter it.
  2. Plot the distributions of price, text length and category; rebalance if cheap items or one category dominate. Split into train and test sets and save them.
  3. Rewrite every item into a short, standard description with a fast, cheap model, using a batch API.
  4. Write a Tester that runs any pricing function over a fixed test sample and reports the average absolute error, with a chart.
  5. Run, in order: a constant baseline, linear regression, bag-of-words regression, a random forest, XGBoost, a small neural network, and two or three frontier models with no training.

Cost: under $1 to preprocess a 20,000-item training set; the reference course reports under $30 for 800,000 items with a cheap provider. You can skip preprocessing by loading the reference course's published datasets (see References).

Curating the data

The raw material is product metadata from the public Amazon Reviews 2023 dataset. The reference course uses eight categories: automotive, electronics, office products, tools and home improvement, cell phones and accessories, toys and games, appliances, and musical instruments. Parse every item into a title, a scrubbed description, a category, a weight and a price, and keep it only if it passes explicit rules, for example a price between $0.50 and $999.49 and at least 600 characters of text.

Then you look hard at what's left: how prices and text lengths are distributed, which categories dominate, whether cheap items swamp the rest. Time spent on data quality here often matters more than any later hyperparameter tuning.

Curation is a design decision

Every filter changes what the model can learn. Too few expensive items and it will never predict a high price; a category that dominates will bias every estimate. Write your rules down, check the distributions after each, and keep the test set drawn from the same distribution as training.

Let an LLM clean the records

Product text is inconsistent: part numbers, marketing fluff, missing fields. Ask a fast, cheap model to rewrite each item into a fixed format (a short title, a category, a brand, a one-sentence description and key details), without part numbers. With thousands of items you don't loop one call at a time: write a small Batch helper that groups items by the thousand and submits them to a provider's batch API, which processes requests asynchronously at a lower price, then collects the results. The same rewriting idea appeared in Week 5's document pre-processing.

Keep two dataset sizes behind one switch: a lite version (around 20,000 training items) and a full version (hundreds of thousands). Use lite while you learn.

One evaluation for everything

Before any model, build a Tester: given any function that takes an item and returns a price, it runs that function over a fixed sample of test items (200 is plenty), records the absolute error in dollars for each, colors each result by how close it was, plots predictions against truth, and reports the average error. Every approach from here to Week 8 goes through the same test, which is what makes the leaderboard below meaningful.

Then the baselines, from the simplest upward:

  • Constant: always guess the average price. Anything worse than this is broken.
  • Linear regression on a few hand-made features such as weight and text length.
  • Bag of words + linear regression: count words and learn a price per word.
  • Random forest: many decision trees, each trained on a random slice, averaged.
  • XGBoost: trees built one after another, each correcting the previous ones' errors.

Add a human baseline too: price 100 test items yourself, without looking anything up. It's humbling, and it tells you what "good" means for this task.

Neural networks and frontier models

A small feed-forward neural network in PyTorch beats the traditional models. Then frontier models are asked to price items with no training at all, using only what they learned about products during pre-training, and the best of them beat everything else so far. That's the key lesson of the week: for tasks that rely on world knowledge, a frontier model with a good prompt is a formidable baseline.

A deeper network with residual connections, trained for a few hours on a GPU, closes much of the gap; it's a good stretch goal if you enjoy PyTorch.

What about fine-tuning a frontier model?

Some providers let you fine-tune their models through the API: you upload training examples as JSONL, start a job, and get a private model ID back. Availability changes; OpenAI, for one, no longer offers fine-tuning to new users. The reference course's published result is still instructive: a small frontier model fine-tuned on these products came out worse than the same model without fine-tuning. Fine-tuning a model that already knows a lot doesn't automatically help. Week 7 does fine-tuning where you control everything.

Takeaways

  • Curate deliberately: explicit filters, checked distributions, matching test data.
  • LLMs in batch mode are a cheap way to normalize messy records at scale.
  • Build one evaluation first and run every approach through it, starting from a constant baseline.
  • Frontier models' world knowledge makes them strong zero-shot baselines; fine-tuning isn't automatically an improvement.

Check your understanding

Why start with a model that always predicts the average price?

Baselines make results meaningful. A complicated model that loses to the average is broken, however impressive it looks.

Why use a provider's batch API to rewrite 800,000 records?

Batch processing trades latency for cost, which is the right trade for offline data preparation.

Frontier models with no training beat random forests and XGBoost here. What's the best explanation?

The task rewards world knowledge. That's why Week 8 combines frontier models with retrieval and specialist models rather than replacing them.

Exercise: beat a baseline honestly

Load the lite dataset. Pick one traditional model and try to beat the chart's number with feature engineering only (for example the brand, or the category combined with weight). Then try one prompt change for a frontier model, such as a single priced example in the prompt. Run each through the same Tester and write down which change helped and by how much.
