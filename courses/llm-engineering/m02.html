Frontier models and your first LLM product

Week 1 makes the first API call, turns it into a website summarizer, and ends with a brochure generator that chains several model calls. Along the way it takes the mystery out of what an LLM API really is: an HTTP endpoint that takes a list of messages and returns the most likely continuation.

By the end of this week you can

  • Call a chat model with system and user messages, and explain what each role does.
  • Point the same client code at OpenAI, Gemini, or a local Ollama model.
  • Explain tokens, and why every call to an LLM is stateless.
  • Chain two model calls, ask for JSON, and stream a long answer back.

The Chat Completions shape

Almost every provider now accepts the same request: a model name and a list of messages, each with a role. The system message sets the job and the tone. User messages are what you ask. Assistant messages are what the model said before. The response is the model's prediction of the next assistant message.

The client library is a thin wrapper

Day 2 makes this point by sending the same request with requests.post to the provider's /chat/completions URL with a bearer token. The openai package doesn't contain a model; it builds that HTTP request and parses the JSON. That matters because so many providers expose OpenAI-compatible endpoints: the same client works against them if you change base_url and the key.

Running locally trades capability for privacy and price: nothing leaves your machine and nothing is billed, but a 3-billion-parameter model is much less capable than a frontier one. The notebooks warn against pulling models such as Llama 3.3 at 70 billion parameters, which are too large for most home computers.

Tokens

Models don't read characters or words. They read tokens: chunks of text from a fixed vocabulary, often a common word, a piece of a word, or punctuation with its leading space. Day 4 encodes a sentence with tiktoken and prints each token ID beside its text. Tokens matter because they're what you pay for, what fills the context window, and why models are oddly bad at things like counting letters: the letters are hidden inside tokens.

The illusion of memory

Day 4's second half is the "aha" moment for many people. Tell the model your name in one call, ask for it in the next, and it has no idea. Every call is stateless. A chat product creates the impression of memory by resending the whole conversation every time. That's why long chats cost more and eventually run out of room, and it's the root of almost everything in later weeks: chat UIs (Week 2), retrieval (Week 5), and agent memory (Week 8) are all ways of choosing what goes into that list.

From one call to a small pipeline

Three techniques arrive together on Day 5:

  • Ask for JSON, with an example. The link-picker's system prompt shows one example of the exact JSON it wants back. Showing one example is called one-shot prompting; several is few-shot. The notebook mentions that a stricter technique, structured outputs, comes in Week 8.
  • Let code do what code is good at. The model decides which links matter; plain Python fetches them. Don't ask a model to do what a function can.
  • Stream long answers. With stream=True you get the reply as a series of small chunks and can show text as it arrives.

Pages that come back empty

The repo's simple scraper reads the HTML the server sends. Sites built with client-side JavaScript (many React apps) send almost no text, and sites behind bot protection may return a 403. The notebook suggests a browser-automation scraper such as Selenium or Playwright for those; there's a Selenium version in the community contributions.

Takeaways

  • A chat API takes a list of role-tagged messages and returns the next assistant message.
  • The client library is just HTTP; OpenAI-compatible endpoints let one client reach many providers, including local Ollama.
  • Models see tokens, and every call is stateless: memory is whatever you put in the messages.
  • Split work into small calls with clear jobs, ask for JSON with an example, and stream long output.

Check your understanding

You send "Hi, I'm Dana" in one API call and "What's my name?" in a second. Why doesn't the model know?

The model only sees what's in the current request. Chat apps resend the whole conversation to create the impression of memory.

To switch the Day 1 summarizer from OpenAI to a local Llama model, what changes?

Ollama exposes an OpenAI-compatible endpoint at localhost:11434/v1, so the same code works.

Why does the brochure generator use two model calls instead of one?

Splitting the work makes each step easier for the model and lets ordinary code handle fetching, which a model can't do on its own.
