What MCP is

MCP is an open protocol, introduced by Anthropic in late 2024 and now widely adopted, for connecting AI applications to tools and data. It's often described as a USB-C port for AI: write a server once, and any MCP-capable application can use it. Three roles are involved:

RoleWhat it isIn this course
HostThe application the user or developer runsYour agent program, or an app like Claude Desktop or Cursor
ClientLives inside the host; holds one connection to one serverMCPServerStdio in the Agents SDK, McpToolset in ADK
ServerA program that exposes tools, resources and promptsfetch, Playwright, filesystem, and the one you'll write

A server can offer three things. Tools are functions the model can call. Resources are data the host can read, identified by URIs. Prompts are reusable templates. Most servers are mainly tools.

stdio servers are launched by the client as a subprocess and talk over standard input and output; they run on your machine with your permissions. Streamable HTTP servers run somewhere else and are reached by URL; they're how companies offer hosted MCP servers. (An older HTTP-with-server-sent-events transport is deprecated.) The newest specification revision is dated 2026-07-28, and current SDKs can run HTTP servers statelessly, with no session carried between requests, which makes them easy to host behind ordinary load balancers.

Using servers from an agent

The async with starts each server and stops it afterwards. list_tools() shows what the model will see. Raise client_session_timeout_seconds above the default (5 seconds) for anything that downloads on first run, as npx and uvx do. For a hosted server, use MCPServerStreamableHttp(name="Docs", params={"url": "https://…/mcp", "timeout": 60}) instead; nothing is launched locally.

To find servers, browse the official MCP registry and community directories such as Glama and Smithery.

Writing a server

A server is your functions behind a decorator. The example wraps a small Account class (balance, holdings, transactions and a strategy, persisted to a JSON file or SQLite); writing that class is a good warm-up, or reuse the one your Week 3 engineering crew wrote.

Add get_holdings and sell_shares the same way. Use it exactly like any other server: {"command": "uv", "args": ["run", "accounts_server.py"]}. Ask an agent "My name is Ed and my account is under Ed. What's my balance, and buy me three shares of Amazon", then read the account back through the resource.

FastMCP, MCPServer, and version 2

Version 2.0 of the MCP Python SDK (July 2026) renamed the server class: from mcp.server.fastmcp import FastMCP became from mcp.server.mcpserver import MCPServer, and the old import now fails. The decorators and run(transport="stdio") are unchanged. Much existing code, including many published servers, still uses the 1.x name, so you'll see both; pin mcp<2 to run older code, and when a third-party server breaks on import, running it with uvx --with "mcp<2" … is a common fix. The standalone fastmcp package is a separate project that keeps the FastMCP name.

Is this server safe to run?

A stdio server is a program running on your machine, with your files, network and keys. Its tool results also go straight into your model's context. Before you add one, ask:

  • Who wrote it, and can you read it? Prefer official servers from the vendor whose service it wraps, or open-source code you've skimmed. Pin a version rather than @latest once it works.
  • What can it reach? Give it only the environment variables it needs, a filesystem server only the folder it needs, and an API key with the narrowest scope the service offers.
  • What can its output make the model do? A fetched web page or a crafted tool description can contain instructions aimed at your model (prompt injection). Keep powerful tools, such as sending email or spending money, away from agents that read untrusted content, or put a human approval step in front of them.
  • Can you limit the tools it exposes? Most clients can filter. In the Agents SDK: tool_filter=create_static_tool_filter(allowed_tool_names=["tavily_search"]).

Context engineering with MCP

Prompt engineering is about the words of your instructions; context engineering is about everything else the model sees when it decides: memory, retrieved documents, tool results and live data. MCP servers are a clean way to supply each kind.

SourceWhat the agent getsTry
MemoryEntities, observations and relations it can store and search across runsTell it about yourself, end the program, ask in a new run what it knows
SearchCurrent information with sourcesAsk about this week's news on a company, with the date in the prompt
Agentic RAGA vector store it fills and queries itself, with local embeddingsResearch a topic with search + store, then answer with only the store connected
IntegrationLive data from a service, such as share pricesWrap a market-data API (or a simulator) as a server with a get_share_price tool

Agentic RAG turns classic RAG around: instead of you loading documents up front, the agent decides what's worth keeping as it works and stores it, and retrieval is just another tool it chooses to use. Connect the memory server to the capstone traders next module and they'll remember what they learned about each company.

Takeaways

  • MCP standardizes how agents reach tools, resources and prompts; hosts hold one client per server.
  • stdio servers are local subprocesses with your permissions; Streamable HTTP servers are remote.
  • A server is decorated functions. SDK 2.x calls the class MCPServer; 1.x called it FastMCP.
  • Treat third-party servers as code you're running: check the source, scope access, filter tools, beware injected instructions.
  • Memory, search, retrieval and live data are all context, and MCP is a clean way to supply each.

Check your understanding

Your agent fails with a timeout the first time it starts an npx server, then works the second time. What's going on?

Raise client_session_timeout_seconds (to 60, say) for servers launched with npx or uvx.

An old server fails with ModuleNotFoundError: No module named 'mcp.server.fastmcp'. Why?

Pin mcp<2 for that server, or update its import.

An agent reads web pages and can also send email. Which risk does that combination create?

Untrusted input plus a powerful tool is the classic prompt-injection setup. Separate them, or gate the powerful tool behind approval.
