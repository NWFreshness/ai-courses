What makes something an agent

"Agent" gets attached to almost anything with a model in it. This module gives you a sharper definition, five workflow patterns that solve most problems before you need an agent at all, and a first project that uses two of them: a panel of models answering one question, ranked by a model acting as judge.

By the end of this module you can

  • Tell a workflow from an agent, and say where a system sits between them.
  • Recognize and sketch the five common workflow patterns.
  • Call several providers through one client shape and compare their answers.
  • Use one model as a judge of others, with structured output you can parse.

Project: a model panel with a judge

  1. Ask one model to write a hard, open-ended question with a short answer.
  2. Send that question to four or more models from different providers (OpenRouter makes this one key), plus a local model through Ollama if you have one.
  3. Collect the answers and give them, numbered, to a judge model that returns a JSON ranking.
  4. Print the ranking with each model's name, and run it three times to see how stable the judge is.

Cost: a few cents per run with small and mid-sized models.

A working definition

A useful definition, from Anthropic's guide to building effective agents, splits systems into two kinds. Workflows are systems where models and tools are orchestrated through code paths you wrote in advance. Agents are systems where the model directs its own process: it decides which tools to use, in what order, and when it's finished.

In practice it's a spectrum of how much control you hand over. Most agentic systems you'll meet share a few traits: several model calls rather than one, models that can use tools, an environment the model can act on and observe, a planner (often the model itself) deciding what happens next, and some autonomy in how long it runs. The more of these a system has, the more it behaves like an agent, and the harder it is to predict.

Start simple

Use the least autonomy that solves the problem. A single well-prompted call beats a workflow when it's good enough; a workflow beats an agent when you can write the steps down. Reach for an agent when the path genuinely can't be known in advance, such as research, debugging or open-ended tasks in a browser, and accept that you're trading predictability and cost for flexibility.

Five workflow patterns

PatternUse it whenExample
Prompt chainingThe task splits into fixed steps and you want to check between themOutline, check the outline covers the brief, then write
RoutingInputs fall into distinct kinds that each deserve their own prompt or modelSend easy questions to a small model, hard ones to a large one
ParallelizationIndependent parts can run at once (sectioning), or you want several attempts to compare (voting)Three reviewers each check one aspect of a contract
Orchestrator-workersYou can't know the subtasks until you see the inputDecide which files a change touches, then edit each
Evaluator-optimizerYou have clear criteria, and feedback measurably improves resultsTranslate, critique, revise until the critic passes it

An agent is what you get when the orchestrator stops being a fixed plan and becomes a loop: the model chooses an action, sees the result, and chooses again until it decides it's done. That loop is Module 2.

What autonomy costs

Handing control to the model brings three risks: an unpredictable path (you don't know which steps it'll take), unpredictable output (you can't fully specify what comes back), and unpredictable cost (a loop can run far longer than you expected). The answers are the same ones you'll practice all course: watch every run with tracing or logs, put limits on turns and spending, and add checks, called guardrails, that catch bad inputs and outputs before they matter.

Many models through one shape

Most providers offer an endpoint compatible with OpenAI's Chat Completions API, so one client class reaches them all; only the base URL, key and model name change. OpenRouter goes further and serves hundreds of models from many providers behind one key.

Model names change often; check each provider's model list and substitute current ones. Calling them in a loop is fine here. Make it faster later with AsyncOpenAI and asyncio.gather, as in Module 0.

A model as judge

Comparing five long answers by eye is slow. Give them, numbered, to a capable model with clear criteria and ask for a ranking in a fixed JSON shape. Hide which model wrote which answer so the judge can't favor a name, and ask for JSON explicitly so you can parse it.

Which patterns did that use? Sending one task to several models at once is parallelization (voting). Using a separate model to grade output is the evaluator half of evaluator-optimizer. Feed the judge's critique back to the losing models and ask them to improve, and you'd have the whole loop.

Judges have biases too

Model judges tend to favor longer answers, the first answer they read, and answers in their own style. Shuffle the order between runs, keep criteria specific, and spot-check a sample of rulings yourself before you trust a judge in production.

Parsing free text

"Here is my ranking: 3, then 1…" breaks json.loads. Ask for JSON only, use the provider's JSON or structured-output mode where it exists, and still wrap the parse in a try that retries once with the error message included. From Week 2, frameworks validate structured output against a Pydantic model for you.

Takeaways

  • Workflows follow paths you wrote; agents choose their own path. Most real systems mix both.
  • Five patterns cover most needs: chaining, routing, parallelization, orchestrator-workers and evaluator-optimizer.
  • More autonomy means less predictable paths, outputs and costs, so observe, limit and check.
  • One client shape reaches most providers; a model judge with structured output turns comparisons into data.

Check your understanding

A support system classifies each ticket as billing, technical or other, then sends it to a prompt written for that kind. Which pattern is that?

A classifier choosing one of several fixed paths is routing. The paths were written in advance, so it's a workflow.

What most distinguishes an agent from an orchestrator-workers workflow?

Workflows can use many models and tools; the defining difference is who controls the sequence of steps.

Why give the judge numbered answers without model names?

Blind judging removes one source of bias. Shuffling the order between runs removes another.

Exercise: close the loop

Turn the panel into a full evaluator-optimizer. Ask the judge for a one-line critique of each answer as well as the ranking, then send each critique back to the model that wrote the answer, asking for a revision. Judge the revised answers. Did the rankings change, and did the worst answer improve the most? Then add routing: send short factual questions to the cheapest model only, and long open-ended ones to the full panel.
