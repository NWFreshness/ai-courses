Set up the workshop

Agents touch more of your machine than a chatbot does: they launch subprocesses, run code, open browsers and send messages. An hour setting up a clean project, the right runtimes, a handful of keys and a spending limit saves days of confusion later.

By the end of this module you can

  • Create a uv project with the packages each week needs, and know which to pin.
  • Install Node (for MCP servers launched with npx) and Docker (for running agent-written code).
  • Store keys for models, search and notifications safely, and cap what you can spend.
  • Write and run async Python, which every framework in this course uses.

Project: a workshop that runs agents

  1. Install git, an editor with Jupyter support, uv, Node 22 or later and Docker.
  2. Create the project and add the Week 1 and 2 packages (commands below).
  3. Create a .env with at least one model key, and list it in .gitignore.
  4. Set up Pushover on your phone and send yourself a test notification from Python.
  5. Run the async smoke test at the end of this module, and set a monthly spending limit on every paid account.

Cost: free to set up. A full run through the course typically costs a few dollars in model calls if you use small models; Pushover is free for a trial, then a one-time fee.

Create the project

Add the remaining frameworks when you reach their week, so you only debug one install at a time. CrewAI is the exception to sharing one environment: it's installed as a command-line tool and creates its own project folders, each with its own environment (Module 4 shows how).

Pin what you depend on

Agent frameworks ship breaking changes often. This course was written against openai-agents 0.15, CrewAI 1.14, LangChain and LangGraph 1.x, Google ADK 2.2 and the MCP Python SDK 1.27 and 2.x. When something here doesn't match what you see, check the version first. uv add "crewai==1.14.4" pins exactly; uv lock --upgrade-package openai-agents moves one package forward deliberately.

Keys in .env

Load it at the top of every script or notebook with load_dotenv(override=True). The override=True matters: without it, a stale key exported in your shell wins over the file you just edited.

A notifier you'll reuse all course

Notice the shape: a plain function with type hints, a docstring that says what it does, and a short string result that says whether it worked. That's exactly the shape a tool needs, and you'll hand this function to agents in almost every week.

Async in ten minutes

Agents spend most of their time waiting: for a model, a web page, a subprocess. Every framework in this course is built on asyncio so that waiting can overlap. Three rules cover nearly everything you'll write.

  • async def defines a coroutine; calling it gives you an object that does nothing until it's awaited.
  • await runs it and waits for the result. In a notebook you can await directly in a cell; in a script, wrap your entry point in asyncio.run(main()).
  • asyncio.gather(a(), b(), c()) runs several at once and returns their results in order. This is how you'll run three agents in parallel in Week 2 and four traders in Week 6.

Run it with uv run smoke_test.py. Three calls should take about as long as one. If you only have an OpenRouter key, create the client with AsyncOpenAI(base_url="https://openrouter.ai/api/v1", api_key=os.getenv("OPENROUTER_API_KEY")) and use a model name like openai/gpt-5.4-mini.

What it costs, and how to keep it near zero

Agents multiply calls: one task can be ten or fifty model calls, and a loop with a bug can make hundreds. Use a small model while you build (every example here uses one), set a hard monthly limit on each provider's billing page, and watch the usage page after your first few runs so you know what a run costs. Hosted tools such as OpenAI's web search are billed per call on top of tokens; free-tier search APIs are cheaper for learning.

Most setup failures

An unsaved .env, or one saved as .env.txt. Running a script with the system Python instead of uv run. npx not found because Node was installed after the terminal opened (open a new one). Docker installed but not running. On Windows, MCP servers launched from a notebook can fail with io.UnsupportedOperation: fileno; run those examples as scripts, or use WSL.

Takeaways

  • One uv project, packages added week by week, versions pinned where frameworks move fast.
  • Node and Docker aren't optional extras: MCP servers and safe code execution depend on them.
  • A good tool is a plain function with type hints, a docstring and a readable result.
  • await one thing, asyncio.gather many, asyncio.run at the top of a script.

Check your understanding

You edited OPENAI_API_KEY in .env, but your script still uses the old key. What's the most likely cause?

By default load_dotenv doesn't replace variables that are already set in the environment.

In a script, you want three agents to work at the same time and collect all their results. Which do you use?

gather runs the coroutines concurrently and returns their results in order. Awaiting in a loop runs them one after another.

Why install Node for a Python course?

Your Python agent launches those servers as subprocesses; Node has to be on the path for that to work.
