Agent = Model + Harness

The model supplies the intelligence. Everything else — the loop, the tools, the context, the checks, the sandbox, the state, the logs — is the harness, and in 2026 that is where most of the difference between a demo and a production system lives. This course teaches you to build that part on purpose.

Who this is for

You can already call an LLM API and you've probably wired up a tool or two. You want to know what separates a toy agent from one you'd let run for six hours unattended, touch real systems, and get paged about. The examples are in Python against a generic Messages-style API (Anthropic's shape, since it's compact), but every idea transfers to other providers and frameworks.

How the course is built

Every module has the same parts, in the same order, so you can skim or go deep:

  1. Objectives: what you should be able to do afterwards.
  2. The lesson, with diagrams, code you can run, and "From the field" notes that summarize what teams at OpenAI, Anthropic, LangChain, Manus, Cognition, Stripe and Thoughtworks have published.
  3. Pitfalls: the failures that show up again and again in published traces.
  4. Takeaways, a quiz that explains every answer, and an exercise.
  5. Read the originals: primary sources for that module.

Modules 1–5 are the foundation and should be read in order. Modules 6–11 can be taken in any order once you have the foundation. Module 12 is a capstone that has you build a production-grade harness, in seven milestones, that uses every strand.

Progress is saved in this browser when you mark a module complete. Nothing leaves your machine.

The one-paragraph version

Treat every agent failure as a harness bug. Give the agent a small, stable map of where knowledge lives instead of an encyclopedia. Design a few high-leverage tools whose outputs are short and whose errors explain how to recover. Manage context like a scarce budget: keep the prefix stable for caching, offload bulk to files, and recite the plan near the end. Pair every guide with a sensor, and prefer deterministic sensors. Make completion a property of an artifact, not the model's opinion. Put hard boundaries in the environment rather than hoping the model behaves. Persist state outside the process so a crash costs one step, not the whole run. Trace everything, grade outcomes with evals, and re-examine the harness every time the model changes. Removing components is as important as adding them.
