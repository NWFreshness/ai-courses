Self-improvement

You now have evaluations, traces and a scoreboard. The last step of Week 2 closes the loop: an improver agent reads the results, proposes a change to the claim agent, a handler approves it, and fresh evaluations decide whether it stays. Done carelessly, this overfits and chases noise; done well, the agent gets better while you sleep, with a person in charge of every change.

By the end of this module you can

  • Ground a model judge in an expert's answer, with a rubric of grades rather than free text.
  • Measure noise, and set objectives, tolerances and a budget for changes.
  • Build an improver that proposes changes for human approval, judged on held-out data.
  • Version an agent's configuration so any change can be compared and rolled back.

Build: an improvement loop

  1. Move the claim agent's prompt, model and reasoning effort into a versioned configuration, with diffs between versions and a Settings page.
  2. Add a judge that grades each rationale against the handler's reason, and calibrate it on claims where you know the right grade.
  3. Run the same version twice on the held-out claims to measure noise.
  4. Build an improver that reads the results and proposes one change; pause for the senior handler's approval; evaluate on the held-out set; keep or roll back.
  5. Add sign-in for handlers, so only Rosa can approve changes and large payouts.

Cost: each round runs two evaluations, so a few rounds cost tens of cents on a small model. Set a credit limit on the key first.

A judge that's grounded

A model judge has the same weakness as the model it judges: it generates plausible text. Ground it: give it the expert's answer to compare against, a rubric with a small set of grades, and ask for a grade, not an essay. Then check it against cases where you already know the right grade.

Noise first, then changes

Run the same version of the agent twice on the same claims and the scores will differ. That difference is noise, and any "improvement" smaller than it means nothing. Set three things before the improver runs:

  • Objectives: floors a version must meet, such as 80% accuracy on the held-out set.
  • Noise thresholds: how much a score must improve to count as better.
  • Tolerances: how much another score may fall, such as cost per claim, before the change is rejected.

The improver

The improver is an agent with four tools: read the results (current configuration, scores, the evaluation set's mistakes, earlier rounds, budget), propose a change, run an evaluation, and propose a change to its own recipe. Proposals pause for approval with HumanInTheLoopMiddleware, so nothing changes without Rosa. A sensible recipe tries cheap levers first, a different model or reasoning effort, before adding rules to the prompt. The recipe's last step improves the recipe itself, which is what makes the loop recursive.

Where overfitting creeps in

The improver sees the evaluation set's mistakes, so it can write rules that fix exactly those claims and nothing else. That's why the keep-or-roll-back decision uses the held-out set, which the improver never sees. But because held-out scores choose which versions survive, they're no longer an unbiased test either. Keep a third, untouched test set for the final number you report to the client.

A run of 25 isn't a ranking

On 25 claims, one claim is four percentage points. A model that scores 84% against another's 80% may simply have been luckier. Run more claims, run them more than once, and treat small differences as ties.

Takeaways

  • Ground judges in expert answers with a fixed rubric, and calibrate them.
  • Measure noise before trusting any improvement; set objectives, thresholds, tolerances and a budget.
  • Proposals pause for a human; held-out data decides; a separate test set gives the final number.
  • Version every configuration so changes can be compared and rolled back.

Check your understanding

An improvement has to clear the noise threshold to count.

Why decide on the held-out set rather than the evaluation set the improver reads?

Judging on data the proposer saw rewards overfitting.

What makes the judge's grades more trustworthy?

Exercise: three rounds

Run three improvement rounds, approving or rejecting each proposal yourself, and keep a log of what was proposed, the held-out scores and the decision. At the end, score the surviving version once on a test set nobody has touched, and compare that number with its held-out score.
