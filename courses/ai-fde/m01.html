The FDE role, and a first agent

Before any client work, two foundations: what a forward deployed engineer actually does, and what an agent actually is. The second fits in thirty lines of Python: a model, one tool and a loop. You'll set up the project and write that agent today.

By the end of this module you can

  • Describe the FDE role and the three disciplines it draws on.
  • Set up a project with uv, a coding editor, Node and an OpenRouter key, on paid or free models.
  • Write an agent from first principles: a model, a tool and a bounded loop.

Build: your workshop and a first agent

  1. Install git, VS Code (or another editor) with the Python and Jupyter extensions, uv and Node.
  2. Create the project with uv init wayfarer --python 3.12 and add openai python-dotenv.
  3. Get an OpenRouter key, put it in .env as OPENROUTER_API_KEY, and list .env in .gitignore.
  4. Write the help-centre agent below and ask it a question it has to browse to answer.

Cost: free on openrouter/free, or well under a cent per run on a small paid model. A typical run through the whole course costs about $10 in model calls, and every step has a free alternative.

What a forward deployed engineer is

The term comes from Palantir, which embedded engineers with its customers in the 2000s rather than shipping software and leaving. The AI labs and many enterprises have since adopted the role. In the narrow sense, an FDE is a senior applied AI engineer working inside a client's organization; in the broad sense, any engineer who solves a real commercial problem with AI and delivers it to the people who use it.

Job descriptions for the role ask for the same mix again and again, and this course is built around it:

Two kinds of experience matter as much as the skills: solving a real business problem, measured in the business's terms, and delivering it to a customer who keeps using it after you leave. The Wayfarer project gives you a rehearsal of both.

The workshop

OpenRouter gives you hundreds of models behind one key and one API shape. The model name openrouter/free routes each request to a free model; free models are limited to a small number of requests a day (more once you've bought some credit), and their providers may train on what you send, so never send them anything confidential. Set a credit limit on your key so a bug can't spend more than you intend.

An agent is a model, a tool and a loop

The agent below answers questions by browsing a tiny help centre, kept in a dictionary so it runs offline. The model can ask to read a page; your code reads it and hands back the text; the loop continues until the model answers or runs out of steps.

That's the whole idea. Everything else in this course, frameworks, harnesses, memory, durability, gateways, is software around this loop to make it reliable, safe and useful for a business. Note three habits already: the tool returns a helpful message when a page doesn't exist, rather than crashing; the loop has a hard step limit; and the system prompt says where the agent's knowledge may come from.

Common setup problems

A NameError in a notebook usually means a cell above wasn't run, so run from the top. A missing key usually means an unsaved .env, or one named .env.txt. If imports fail, check the notebook is using the project's .venv kernel. A free model that wanders off course isn't broken: run it again, or try a paid one.

Takeaways

  • An FDE combines AI engineering, AI architecture and forward deployment, and delivers to a real customer.
  • An agent is a model with tools in a loop, working toward a goal.
  • Even the smallest agent needs a step limit, tools that fail gracefully and a clear source of truth.

Check your understanding

What distinguishes a forward deployed engineer from an engineer who builds AI features in-house?

The role is defined by being embedded with a customer and accountable for an outcome there.

Why does the loop have a max_steps?

The model decides when to stop, so your code needs its own limit.

Which data is safe to send to a free model on OpenRouter?

Free tiers often allow training on inputs. Keep real client data on paid providers whose terms you've checked.
