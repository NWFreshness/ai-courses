Agentic RAG, MCP and memory

Some claims turn on facts that aren't in the claim or the policy: whether a storm had been named when the customer bought cover, or what an unfamiliar product actually is. Handlers know these things or look them up. Today the agent gets a long-term memory it can search for itself, served over MCP, and you measure exactly how much it helps.

By the end of this module you can

  • Explain RAG and agentic RAG, and evaluate retrieval with precision, recall and MRR.
  • Choose between RAG, agentic RAG and fine-tuning for a client's need.
  • Connect an agent to a vector store through an MCP server, with read-only access.
  • Tell short-term from long-term memory, and design what an agent remembers.

Build: a memory of outside facts

  1. Write 25 claims that each need one outside fact, and a list of 30-odd facts (dates of named storms, product descriptions, airline strikes) with the claim each one decides.
  2. Run a local Qdrant MCP server, and have an assistant agent store the facts with qdrant-store.
  3. Give the claim agent only qdrant-find: it can search the memory but not change it.
  4. Run the claims with and without memory in Langfuse, scoring accuracy and a found_fact score for whether the right fact came back.

Cost: cents. Qdrant runs locally and embeds text with a small local model, so there's no extra key.

RAG and agentic RAG

Retrieval-augmented generation chunks documents, embeds each chunk as a vector, and at question time retrieves the nearest chunks and puts them in the prompt. Classic RAG does one retrieval, with the user's words as the query. Agentic RAG makes retrieval a tool: the agent writes its own queries, searches as often as it needs, rephrases when a search comes back empty, and decides when it knows enough. It can do this itself or through a research subagent, which keeps the search results out of the main context.

ScoreQuestion
Precision@kOf the k results returned, how many were relevant?
Recall@kOf the relevant items, how many were in the k returned?
Mean reciprocal rankOn average, how high was the first relevant result? (1 for first place, ½ for second…)
Found fact (agentic)Across all the agent's searches, did the fact this claim needs come back at all?

RAG, agentic RAG or fine-tuning?

Use RAG when the knowledge changes or must be cited; agentic RAG when the right question isn't obvious from the input; fine-tuning when you need a new skill or format rather than new facts. For facts that keep arriving, agents learn best by updating their memory, which you can inspect, correct and delete, rather than their weights.

MCP for your own agents

The Model Context Protocol connects AI applications to tools and data. A host (your agent program) holds a client per server; servers expose tools, resources and prompts; stdio servers run as local subprocesses and Streamable HTTP servers run elsewhere. MCP earns its place when a tool is shared, by several agents, several teams or off-the-shelf apps, or is maintained by someone else. A tool only your own agent uses is usually simpler as a plain function.

Giving the claim agent qdrant-find and not qdrant-store is a small permission decision with a big effect: a strange claim can't plant a false "fact" for later claims to find.

Short-term and long-term memory

Short-term memory is the conversation or run in progress: messages, tool results, the to-do list. Long-term memory outlives the run. Decide what goes in it deliberately: facts about the world (as here), facts about each customer, summaries of past claims, or the agent's own lessons. Managed memory services, such as the one you'll use in Week 3, extract these automatically with strategies and keep each customer's memories in their own namespace.

Two practical snags

uvx ignores your project's Python version, and some MCP servers can't install on the newest Python, so pin one with --python 3.12; otherwise you'll see a vague "connection closed" error. And Qdrant's local mode allows one process at a time, so don't run the librarian and the claim agent against the same folder at once.

Takeaways

  • Agentic RAG lets the agent write its own queries and search until it knows enough.
  • Measure retrieval separately from answers: precision, recall, MRR, or whether the needed fact came back.
  • Use MCP for shared or third-party tools; give agents the narrowest access, such as read-only search.
  • Memory is a design: decide what's remembered, for whom, and who can write it.

Check your understanding

The correct fact is returned third out of three. What's that query's reciprocal rank?

Reciprocal rank is 1 divided by the position of the first relevant result.

Why does the claim agent get qdrant-find but not qdrant-store?

Least privilege applies to memory as much as to payments.

A tool will only ever be used by your own claim agent. Should it be an MCP server?

MCP is an integration standard; use it where integration is the problem.

Exercise: is a vector store even needed?

Replace the vector search with a plain word search over a JSON file of the same facts, and compare found_fact and accuracy. Then give each customer a small Markdown memory file the agent can read and append to, and decide what it should and shouldn't be allowed to write there.
